# 大肥鱼完整操作步骤

本文按实际部署顺序整理。示例 QQ 和 IP 已替换；旧记录中的文件位置以 `D:\dafeiyu` 为示例。不要把本仓库当成含账号和声音模型的整机备份。

## 1. 准备账号与组件

准备一个独立的机器人 QQ、主人 QQ、DeepSeek 官方 API Key、北京地域的阿里云百炼 API Key。机器人 QQ 和主人不是同一个账号。先在 Windows 本机安装验证，再迁移云端。

下载上游 [大肥鱼项目](https://github.com/whyever77/dafeiyu-astrbot)、[AstrBot](https://github.com/AstrBotDevs/AstrBot)、[NapCat](https://github.com/NapNeko/NapCatQQ)。本次固定 AstrBot 4.29.4、NapCat 4.18.42、Python 3.12.13。上游原有的人格、插件安装方式以其文档为准。

目录约定为 `D:\dafeiyu\AstrBot-4.29.4`、`NapCat`、`local-voice`、`custom-plugins`、`云端部署`。安装软件及其依赖后，再复制本仓库对应脚本。Python 环境和第三方程序不包含在资料包内。

## 2. 连接 QQ 与聊天模型

1. AstrBot 面板监听本机 `6185`，NapCat WebUI 监听本机 `6099`。
2. 从 NapCat 启动日志取得 WebUI Token，用机器人 QQ 扫码并在手机确认登录；不要用主人账号登录机器人。
3. 在 AstrBot 创建 aiocqhttp/OneBot 反向 WebSocket 连接，本机地址为 `ws://127.0.0.1:6199/ws`。NapCat 客户端与 AstrBot 的 Token 必须一致。
4. 添加 DeepSeek 官方提供商，在面板填写自己的 API Key，执行连接测试，再设为默认模型。原部署最后验证的模型 ID 为 `deepseek-flash`，提供商 ID 为 `deepseek_2`；重新部署应以自己账号实际可用模型为准。
5. 导入 `persona/大肥鱼-人格.md`，设为默认人格。
6. 将主人 QQ 设为唯一管理员。关闭聊天白名单以允许所有人私聊；群聊保留 @、引用机器人或“大肥鱼”名称唤醒。
7. 由主人发送“在吗”，以实际收到回复为首次验收，不能只看进程启动。

## 3. 听语音与云端声音

在“模型提供商 → 语音合成”创建 `bailian_voice`，填写北京地域的百炼 Key，使用 `cosyvoice-v2`。本次最终云端备用为龙嫱 `longqiang_v2`；曾试过龙小夏等声音，试听后才选择。

语音识别使用 `qwen3-asr-flash`。分别验证真实录音听写与一条语音合成，再开启语音回复。设置 `trigger_probability=0.6`、`dual_output=false`：长期约60%语音、40%文字，并不是每十条固定六条语音。合成失败时回复文字。

## 4. 表情包与主人权限

安装上游表情转换、日程感知、B站活动插件，以及 [meme_manager](https://github.com/anka-afk/astrbot_plugin_meme_manager) 5.3.5。导入上游蓝色大肥鱼表情包，设为默认图库。本次为157张动态图、15个分类，每次按情绪少量配图。图库体积大且属于第三方资源，本仓库只记录来源。

安装 [黑名单插件](https://github.com/AstrBotDevs/astrbot_plugin_blacklist)。原部署将消息过滤优先级提高到 `1000000`，保证先拦截被限制用户；管理指令保留 AstrBot 管理员权限，只有主人账号列在管理员表里。

- `/ban @成员`：按 QQ 账号全局禁止对方使用机器人。
- `/pass @成员`：解除限制。
- `/banlist`：查看名单。

指令需要真正的 QQ @成员，不是纯文字号码；这不会禁言或踢出 QQ 群。限制应在重启后仍存在，普通用户不能执行管理指令。

## 5. 迁移云服务器

先备份 AstrBot 的 `data`、NapCat 配置和 QQ 登录目录；这些备份只能私下保存。服务器运行目录约定为 `/opt/dafeiyu`。

云端以 Docker 运行 AstrBot 和 NapCat，容器名为 `dafeiyu-astrbot`、`dafeiyu-napcat`，加入同一个 `dafeiyu` 网络。挂载共享 `/opt/dafeiyu/data:/AstrBot/data`，否则图像和语音路径不能跨容器读取。

云端 WebSocket 客户端目标改为 `ws://astrbot:6199/ws`。AstrBot 在容器内监听 `0.0.0.0`；管理端口只映射服务器 `127.0.0.1:6185` 和 `127.0.0.1:6099`，不要把容器内监听与公网开放混淆。参考 `云端部署/prepare-cloud.py` 和两份 `start-*.sh`。

这两份启动脚本使用原环境构建的本地镜像名，重新部署须先从对应版本的官方源码构建或导入自己的兼容镜像，再调整名称；本仓库不分发整机镜像。AstrBot 基础镜像还需补齐空间、语音、表情包所需依赖，见原云端记录。

用管理 SSH 连接转发本机 `16185→6185`、`16099→6099` 后访问面板。`云端面板.bat` 会调用相应脚本，密码在登录窗口输入，不保存在脚本中。关闭这个连接不影响机器人继续运行。

迁移完成后停止 Windows 上的 QQ/机器人副本，避免同账号冲突。服务器配置 `restart unless-stopped` 并确认 Docker 随系统启动。原部署保留了 CentOS 7，为兼容使用 Docker 24.0.9；这是旧系统兼容记录，不是新服务器的系统推荐。

## 6. 处理低内存掉线

原服务器仅1GB内存，出现 QQ/Python 被系统 OOM 结束。已建交换空间但 `swappiness=0`，没有实际参与回收。

处理顺序：先看内核 OOM 记录、`free -m`、`swapon --show`、容器重启次数，再调整。原实例增加3GB交换空间，将主机、Docker父级及容器的 swappiness 设为60；容器内存上限700MiB、内存加交换上限1800MiB。两容器的上限不代表物理内存足够，应监控实际使用量。保留修改前配置，并验证交换空间确实被使用，最后主人发消息确认恢复。

## 7. QQ 空间与主人审核

安装 [QQ空间Ultra](https://github.com/diaomin66/astrbot_plugin_qzone_ultra) 0.9.0，绑定机器人自己的 QQ 空间。关闭自动发表、自动评论和直接发表的模型工具。再安装 `custom-plugins/astrbot_plugin_fish_qzone_drafts` 1.2.3，配置主人与机器人 QQ。

默认只在主人要求时生成：`/找素材` 或 `/找素材 猫咪`。它联网找趣图，用大肥鱼第一人称写三条约25–70字的趣味文案，私发给主人审稿；没有定时推送。

主人使用 `/看稿`、`/过稿 编号`、`/拒稿 编号 原因`。只有过稿才发表，正文和配图必须与审核版本一致。保留文件校验、重复过稿不重复发表、失败保稿和普通用户拒绝等保护。

手机截图中的入口叫“投稿至空友爱看”，与“所有人可见”是两个设置。配套代码会先发说说，再用机器人本人动态 ID 投稿，并查询平台状态。`101` 是平台审核中，`102` 是审核通过，不能把提交成功说成已收录。

`quota_fallback_normal=true`：额度用完后过稿仍发普通 QQ 空间，不自动次日补投。`/投稿状态 编号` 查询，`/补投稿 编号` 只补投原动态，不重新发一条。额度接口异常时保留待审，不能把失败当作额度为零。

发布参数设为所有人可见后，还需检查整个 QQ 空间是否另设访问限制。空友入口与协议可能变化，重新部署须实测，勿仅按历史记录断言可用。

## 8. 指定声音：下载与准备

本次采用 [GPT-SoVITS](https://github.com/RVC-Boss/GPT-SoVITS) v2ProPlus，在 Windows RTX 5060 Laptop 8GB 上训练。说话与聊天模型分开：服务器继续聊天，本地只负责合成音频。

1. 在 `local-voice/.venv` 建独立 Python 3.12 环境。
2. 先装官方 CUDA 12.8 的 `torch==2.7.1+cu128` 和 `torchaudio==2.7.1+cu128`。
3. 克隆 GPT-SoVITS 到 `local-voice/GPT-SoVITS`，本次源码提交前缀为 `04a44eb`；应用 `windows-single-gpu.patch`。
4. 运行 `prepare_requirements.py`，再安装生成的 `requirements-windows.txt`。Windows 使用 `opencc-python-reimplemented`，固定 CPU `onnxruntime==1.22.1`，避免 CUDA 版本冲突。
5. 运行 `download_models.py` 下载并核对 v2ProPlus、GPT、Hubert、BERT 和说话人模型。
6. 运行 `download_aux_models.py`、`prepare_language_resources.py`。检查 G2PW 解压目录、中英混读资源及 fast_langdetect 模型，服务启动前须就绪。
7. 转录工具将 faster-whisper 安装到单独 `asr-tools` 目录，避免其 NumPy 版本干扰训练环境。用 ffmpeg 解码为16k float32数组后识别，绕过 PyAV 19 与旧识别接口的不兼容。

模型文件、驱动、ffmpeg、Python 和录音需要自行准备。锁定依赖见 `requirements-lock.txt`，它是原环境记录，不要在不匹配的显卡上直接照搬 GPU 包。

## 9. 素材、降噪与训练

先保留录音原件，只处理副本。本次第6份约155秒；第7份用户确认发错，完全排除；第8份约132秒。不要把“第7份没用”误解为删除用户原文件。

第一版用16句约83秒；第二版用 [DeepFilterNet](https://github.com/Rikorose/DeepFilterNet) 0.5.6 清理第6、8份，筛选24句约120秒，在独立 `dafeiyu_clean68` 实验中训练，不覆盖旧权重。`prepare_clean_training.py` 保存了这次选段规则，换素材时要重新校对，不能直接复用旧时间戳。

流程为转录、交叉听写、人工筛除不确定句、文本特征、Hubert、说话人特征、语义特征、SoVITS音色训练、GPT发音训练。`train_voice.py --experiment 名称 --directory 数据目录` 支持隔离实验，批次2，音色8轮、GPT15轮。训练前停止本地声音以释放显存，云端自动用备用音色。

素材增强须先转单声道48k，再用 `deep-filter.exe -D`，训练切片用32k PCM。合成结果还会做最多30dB的本地降噪。下载降噪程序到 `local-voice/denoise/deep-filter.exe`，程序与模型不提交 Git。

## 10. 先试听，再启用

`preview_voice.py` 生成三个未见训练句，输出独立的配置、清单、降噪前后 WAV。检查是否静音、削波、严重漏读，再用 `check_previews_cloud.py --directory 试听目录` 做独立听写校对。

听写匹配度仅反映文字，不是声音自然度评分。必须把试听发给主人听，选定后才将相应 `voice-settings-preview.json` 复制为 `local-voice/trained-voice.json`。此次用户明确要求以后先试听、再改，不要自动回退音色或替换已选版本。

最终净化权重为 `dafeiyu_clean68_e8_s384.pth` 和 `dafeiyu_clean68-e15.ckpt`，参考句采用第6份净化切片，第8份仍参与训练。参考音频路径和文字必须一致。正式与试听都采用完整句段 `cut2`，关闭本机上出现漏读的加速路径。

## 11. 自动连接、备用与联网恢复

安装 `astrbot_plugin_fish_hybrid_voice`，仍使用原来的 `bailian_voice` 提供商。它只增加本地优先路由，失败时调用原百炼方法，不复制 API Key、不改变60%语音概率。

本地接口 `127.0.0.1:19880`，所有请求要求随机 Bearer 凭据。专用服务器账号 `fishvoice` 只允许语音连接和固定清理命令，无任意终端权限；公钥放服务器，私钥仅本机保存。执行 `prepare_server_bundle.py` 生成的连接包含请求凭据，只能私下传输，不可上传 GitHub。

由管理员先阅读 `setup-server.sh`，确认路径、现有配置备份和 ACL 限制，再在服务器配置。连接将服务器共享目录中的 `voice.sock` 转到本机19880，不增加公网语音端口。

启动入口 `启动本地声音.bat`，后台管理器保持服务和连接运行；`停止本地声音.bat` 请求完整停止。重复启动不会重复加载模型。电脑重启或主动停止后需要重新点启动，单纯断网恢复不需要。

服务器与本机都设10秒保活、连续2次无响应后释放连接。关键是服务器也释放旧会话，否则旧 socket 会阻挡重连。管理器每5秒重试；云端本地失败后退避15秒，下一次语音会自动再试本地。

验收采用仅阻断当前专用连接35秒的测试，管理器及模型进程不重启：先实际生成本地音频，再确认断开时云端音色，恢复后再次生成并核对日志来源为本地。测试结束必须删除临时规则。不要拿“提供商可用”单独当作本地恢复证据。

## 12. 备份与日常维护

私下备份 AstrBot data、NapCat登录/配置、插件数据、训练配置和权重、语音私钥及请求凭据。任何迁移都先备份再改，QQ 空间测试不能未经主人过稿公开发表。

排查顺序：服务器在线和内存 → QQ是否登录 → OneBot连接 → 对话模型 → 语音来源 → 本地服务和隧道。QQ消息由服务器发送，本地断网只影响本地声音，不应影响正常云端聊天。

公开分享只包含代码、模板和已脱敏的步骤。安装目录、真实API密钥、登录快照、聊天与声纹素材均不进入仓库。
