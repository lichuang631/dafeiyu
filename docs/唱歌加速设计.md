# 本地唱歌加速与回传修复

用户已批准本地显卡分离、复用已加载模型、成品缓存三项方案；普通说话音色保持不变。基准为同一60秒《叹云兮》试听，原完整处理约66.7秒，其中CPU分离23秒。

先修回传：原唱歌处理器在异步生成器中逐次yield进度和音频；meme_manager的消息后置钩子停止事件后，管线终止生成器，本地任务虽已完成却未继续回传。改为普通异步处理器，直接await event.send发送所有进度和音频，不改AstrBot或meme_manager。

缓存按查询、参考音频与模型/参数版本生成键，原始查询可归一空格，不能把不同歌手或音色合并。仅复用成功且文件校验通过的分段，缺文件、内容变化、超时或旧模型失效时重新生成。复用已有完成任务时保留试听来源、原曲范围及分段信息。

加速环境与旧环境隔离，测试CUDA12兼容的ONNX Runtime GPU，用同一个MDX模型和原30步、原参考音频进行比较。保持CPU/旧处理路径可回退。只有确认实际使用CUDA、音频完整且未明显退化才启用。

模型复用采用受管理器控制的本地引擎，仅监听回环地址、使用既有Bearer凭据；单次任务受GPU锁控制，停止管理器时子进程一起结束。模型按需加载并复用，须实测空闲显存及原说话功能，必要时限制闲置保留时间，避免持续占满8GB显存。

验收包括：带停止事件钩子的真实处理器仍发送全部音频；相同歌曲/音色缓存命中、音色变更/文件篡改不命中；同曲60秒冷启动/模型复用/缓存耗时比较；原语音正常、无新公网端口、管理器停止和恢复均能控制新增子进程。上传脱敏代码与文档到原仓库，不包含缓存音频和模型。
