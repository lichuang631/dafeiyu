# 本地唱歌加速与长时间等待修复

2026-11-07，用户同意保留现有声音、优化本地分离和模型加载，并增加成品缓存。实现保持原MDX模型、原净化参考音频、Seed-VC 30步及原混音参数，不更换普通说话音色。

## 实测速度

同一60秒鞠婧祎《叹云兮》公开试听，后台已经启动：

| 场景 | 搜歌到混音、分段完成 | 备注 |
|---|---|---|
| 原版本 | 约67秒 | CPU分离，每次重新加载换声模型 |
| 加速版首歌 | 约44秒 | 按需加载模型 |
| 模型仍在内存时处理 | 约29秒 | 复用模型 |
| 相同歌曲成品缓存 | 本地约0.01秒 | 无需再转换，上传QQ仍需时间 |

显卡分离单独测得约5–7秒，原CPU分离约18–23秒。首次分离还包含模型加载，耗时更长。GPU和CPU分离后的人声比较信噪比约95.7dB，时长均为60秒；这个数字反映数值差异，不是声音好听程度的评分。

GPU模型保留后，普通说话合成已验证成功。原说话配置文件在修改前后校验值相同。以上是该音源和本机的实测，不保证其他歌长、网络、显卡负载下同样快。

## 曾经出现的“不回传”

原1.0.0唱歌插件在异步生成器中yield进度和音频。发送第一条“正在处理”提示后，meme_manager的消息后置钩子停止事件传播，AstrBot管线中断了生成器。本地实际上已经唱好，后续音频却没有继续发回。

1.0.1改用普通异步处理器，直接await event.send完成进度和所有分段发送，不修改AstrBot或meme_manager。用户随后在真实QQ重发同一指令，已确认收到两段语音。专门的回归测试模拟消息后置钩子停止事件，仍须发送全部音频。

当前1.0.2还增加每30秒等待提示、阶段超时处理、失败后解除点歌冷却。不能承诺所有网络故障都不会发生，但不会只靠一条“处理中”让用户一直等。

## 缓存

`singing/cache.py`为成功成品建索引，包含查询、参考声音文件内容、模型文件状态及处理版本。仅归一空格，不把不同歌手的同名歌混为一首。缓存最长7天，每次取回都检查分段大小与SHA256；缺失、篡改、换声音或换模型后不命中。

仅缓存完整成功任务；仍保留“公开试听片段”和最长五分钟的说明。缓存索引及音频留在本机，不上传GitHub。私有API的`refresh=true`仅供维护测速，正常QQ点歌不暴露这个选项。

## 显卡环境与模型复用

在 `singing/.venv-gpu` 创建独立Python 3.12环境，先安装官方CUDA12.8版Torch2.7.1和torchaudio2.7.1，再安装 `requirements-gpu.txt`。ONNX Runtime GPU固定1.22.0以匹配CUDA12，不能直接换成默认CUDA13的新版本。原 `singing/.venv` 保留为旧处理路径。

`engine_service.py`只监听 `127.0.0.1:19881`，请求需要已有语音Bearer凭据。此端口不转发到公网，也不新增服务器账号或密钥。云端仍通过原来的Unix socket访问19880任务接口。

管理器按需维持轻量引擎进程，第一首时加载分离和Seed-VC模型，后续歌曲复用。GPU计算与普通说话共用互斥锁；忙碌时普通语音沿用原云端备用。模型闲置90秒后进程释放显存，管理器重新启动轻量待命进程，下一首重新加载，已缓存歌曲无需加载模型。

ONNX使用CUDA提供程序，限制临时显存并在每次推理后收缩内存池。测试发现1GB上限不够，最终采用2GB上限及内存收缩，避免分离缓存长期挤占8GB显卡。

复制 `singing/acceleration.example.json` 为同目录的 `acceleration.json`，准备好GPU环境后设 `enabled=true`，停止并重新启动本地声音管理器。设为false后新任务回到旧处理路径。停止入口必须同时退出说话、唱歌引擎及SSH连接；本次已验证两个本地端口均退出，再重新启动恢复正常。

## 进度与超时

搜索、分离、换声和混音分别记录阶段。客户端等待超过30秒仍未进入下一阶段时补发进度提示。搜索最多等待约120秒；分离、换声根据歌曲时长给上限；60秒输入的换声阶段超过约120秒没有更新会被停止并明确报错，整个任务仍有900秒总上限。长歌曲的允许时间更长。

超时会停止当前任务进程树，并只取消对应任务的加速引擎；管理器恢复引擎待命，不影响服务器聊天。失败后普通用户可重试，不必因一次失败再等完整点歌冷却。网络中断时可能需要重发同一指令，成功成品可从缓存取回。

## 验证方式

`benchmark_engine.py --source 音源文件`只测分离与换声的冷/热两次，并确认模型保留时普通说话可用。`benchmark_pipeline.py`通过正式私有接口测完整流程两次和缓存一次，不向QQ发送。

测试包括HTTP鉴权、任务幂等、忙碌限制、非法URL与路径、音频分段边界、指定歌手匹配、显卡锁释放、缓存校验、换声音失效、阶段超时停止及消息后置钩子中断回归。实际QQ回传、云端音频取回和管理器停止/重启另作集成验收。
