# 大肥鱼空间灵感与审稿

用户已选择：叫大肥鱼找素材时再生成，不定时推送。

流程：主人发“找素材”或用自然语言要求寻找空间灵感；插件通过 Bing 图像搜索挑选趣图和照片，沿用当前大肥鱼人格，按每张图的主题生成三条第一人称原创草稿；图文和来源只私发给主人 100000001，保存到 QQ空间Ultra 的待审稿件中。主人使用现有“过稿 编号”发布选定的正文和图片，或“拒稿 编号”放弃。用户已选择网上图片，不使用本地表情包替代。

风格改为每条约25–70字的轻松吐槽、摸鱼、贪吃、发呆和可爱反差，减少科普与说教。图片标题和搜索主题是参考资料，不冒充照片为机器人自己拍摄。搜索摘要仍保留为可关闭配图后的文字模式，但默认开启配图；图片搜索不足三张时明确报错，不静默交付纯文字稿。

实现为一个轻量配套插件，复用现有模型、人格、空间授权、稿件库和审核发布命令，不启动浏览器，不新增后台定时任务。网页摘要作为资料处理，生成调用不提供任何工具。来源链接只用于私聊审核，不混入发表正文。

图片只从固定 Bing 图片缓存主机获取，不执行页面脚本或下载任意来源站地址；限制大小、类型与尺寸，过滤素材站水印标题和与动物主题明显无关的结果，按文件哈希留存，审稿和发表使用同一张图片。

权限和发布边界：只有主人可以生成草稿；普通用户不能触发搜索、模型调用或查看草稿。停用原有两个直接发表的模型工具，防止模型把“找灵感”误解为允许发表；保留主人的手工发表和审核命令。关闭投稿人署名，避免发表内容出现“来自主人的投稿”。自动发表和自动评论继续关闭。

验证：检查普通用户被拒绝、搜索失败时不编造素材、生成失败时不创建空稿、草稿内容和来源对应、每次生成不调用发表接口、直接发表模型工具停用、现有审核命令仍只对主人开放；最后由主人在真实 QQ 中触发并核对草稿。

2026-11-07 补充：用户明确要求只审核，发表和空友投稿全部由大肥鱼执行。通过腾讯官方 QQ Android 9.3.80 的协议定义，找到对已发表本人动态执行投稿的 `QzoneV4Service.trpc.qqappai.qzone_archive.FeedStatusService.SetFeedStatus`。投稿状态项为类型19、值1；原生 `QzoneContributeLimiter.Query` 只读查询已跑通，返回剩余3次、业务码0。

实施路径：主人 `/过稿 编号` → 检查登录账号与平台投稿额度 → 复用原有审核图文发表 → 从服务器返回的本人动态中取得真实 feed_id → 提交官方投稿请求 → 再读动态的空友审核状态，报告“已投稿，等待平台审核”或具体失败情况。只有保存于本插件来源账本、由主人确认的草稿走自动投稿。未审核的稿件不写入；普通用户不能调用；投稿失败仅重试已发表的同一条动态，不再发表重复说说。记录状态和原始发表编号，重启后仍能区分已发表与已投稿。

使用现有 `/过稿`，增加 `/投稿状态 编号` 查看、`/补投稿 编号` 在已发表且来源匹配时只补投稿。底层仅开放固定的查询和投稿命令，不向模型提供原始发包工具。先完成协议与审稿流程测试，再让主人选一条现有草稿过稿验证真实投稿，不擅自挑稿发表。

额度用完后的规则已按主人确认上线（1.2.3）：默认 `quota_fallback_normal=true`，主人审核通过后，即使空友爱看没有剩余额度，仍发表到普通 QQ 空间并明确回复“本条未投稿”，保存原动态编号及 `ordinary_only` 状态。额度恢复后不自动补投，重复过稿或查询状态也不补投；只有主人发送 `/补投稿 编号` 才补投该原动态。发表与提交之间额度耗尽时使用同样处理，不重发。无法确认额度或 QQ 账号异常时仍保留待审，不能误当成额度用完。
